GitHub 项目同步约定

仓库：https://github.com/lianggeming14/liangzihu-ontology-traceability
所有者：lianggeming14；分支：main；可见性：Private。

用户已授权：本项目现有及后续生成的成果都上传一份。每次交付前同步，无需重复询问同一仓库的正常文件上传。
同步包括方案、原始项目文档、源码、迁移、契约、测试、图片、预览、交付压缩包和构建程序。
排除本机凭据、认证缓存、运行数据库/资产、依赖及系统临时文件，规则见 .gitignore。

正常 Git 网络环境：
  python tools/sync_to_github.py --message "说明本次新增或修改"
或双击“同步到GitHub.cmd”。脚本先拉取远端状态；出现冲突或远端分歧会停止，不强制覆盖。
首次网页导入之后，本地仓库尚无提交时，会先取远端 main 为基线，保留工作区文件，再检查并提交本地变化。
需要本机 Git 已具备该私有仓库正常访问身份；不要将访问令牌写入脚本或仓库。

本次环境中 git 无法直连 github.com:443，且项目 .git 元数据只读；网页已登录正确账号。采用以下可复核导入流程：
1. 运行 python tools/build_github_snapshot.py --working-tree，仅读取 Git 的忽略规则和工作区文件，不修改 .git。正常可写环境也支持 git add -A 后运行默认索引模式。
2. .github-upload 中产生分卷 ZIP 和 snapshot-manifest.json；清单记录每个文件与归档的 SHA-256 和大小。
3. 通过该私有仓库网页，把所有分卷、manifest 和 tools/restore_github_snapshot.py（首次以根目录文件上传）放到仓库根目录。
4. 首次通过网页建立 .github/workflows/import-snapshot.yml。以后该工作流保留，只有手动触发才会运行。
5. 在 Actions 中手动运行 Import reviewed project snapshot。它只在本仓库校验和还原指定清单，保留原目录，不执行快照中的业务代码，不删除未列出的文件。
6. 验证还原文件数/摘要和远端提交后，才能报告同步完成。临时上传分卷仍保留在远端，作为此次备份副本。

GitHub Actions 使用官方 checkout 及仓库范围的临时 GITHUB_TOKEN，不创建新的长期令牌、不修改成员权限、不开放公网服务。工作流没有定时触发器。
来源参考：https://github.com/actions/checkout ；https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow

这个约定记录的是每次项目工作的同步流程，不是系统后台监听。用户在其他程序手动修改文件时，不会凭空自动上传；可运行同步脚本或在下次项目工作时同步。
