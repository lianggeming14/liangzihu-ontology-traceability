也可运行“同步到GitHub.cmd”。同步前检查新增文件与敏感信息，先处理远端新提交；禁止强制覆盖或 force push。推送后核对 main 的提交和更新文件。
采用受控稀疏工作副本时，只提交本轮已审查的精确文件列表与清理列表，不把其他尚未完成的本地改动一起上传。

网络不可用时的备用快照流程：
1. 使用 tools/build_github_snapshot.py 生成经过 SHA-256 清单核验的 ZIP 分卷。
2. 通过正常 GitHub 登录方式把本次分卷和 snapshot-manifest.json 放在 incoming/。该目录被本机 Git 忽略；使用 Git 上传时只对已经审查的确切文件显式添加。
3. 手动运行 Actions → Import reviewed project snapshot，在 manifest 输入填写 incoming/snapshot-manifest.json，或本次清单的仓库相对路径。
4. 工作流使用 tools/restore_github_snapshot.py 校验全部成员后还原项目，不执行快照中的业务代码，不删除未列出的项目文件。缺清单或摘要不匹配会失败。
5. 核对提交和还原结果后，清理本次已消费的确切传输分卷与清单。不要把旧 ZIP 永久堆在仓库根目录。恢复工具保留一份在 tools/，无需根目录重复副本。
