# 本体数据库仓库更新与清理

日期：2026-11-04。目标为 **lianggeming14/liangzihu-ontology-traceability**，默认分支 `main`，维持公开。

## 入口与运行配置

本轮把十分之一样本放到[仓库首页](../../../README.md)的首要入口，提供样本说明、截图、完整 SQL、回读报告及配置。当前工程为 `ontology-platform/`；旧 `implementation/` 继续作为历史工程，不与当前平台启动方式混用。

[配置示例](../../config/fish-review.example.json)只保存来源路径、私有环境文件路径、固定样本 schema 和输出目录。密码只保存在被忽略的 `.runtime/` 环境文件。路径可按机器配置；离线 `--plan` 不要求数据库或凭据，`--verify` 仅回读已有样本，建库入口拒绝覆盖已有 schema。来源仍以固定 ZIP、Git blob、SHA-256 及 557 个成员的校验为依据；不执行 ZIP 中的生成器。

仓库新增只读的 `Check ontology database repository` 工作流，检查首页链接、配置、64 张表 / 1,346 个字段、抽样计数和清理状态，不连接数据库、不恢复全量导入。具体重建步骤见[样本说明](../fish/review-sample/README.md)。

从当前 Git 树移除 **122 个文件、126,655,740 字节（约 120.8 MiB）**，精确路径、原对象摘要、大小证据和原因见 [repository-cleanup.json](repository-cleanup.json)。

| 项目 | 删除文件数 | 原对象字节 |

两份文档目录中的 **21 个源文件、图示和 QA 文件**保留；正式 Word、SQL、迁移、数据字典、样本页面、测试和历史工程均保留。匹配原 Git 对象摘要的 112 个本地缓存文件也已清理，没有递归删除目录，没有触及运行数据库。

新增忽略规则阻止旧上传分卷、文档渲染缓存及本机配置重新进入正常提交。手动快照工作流保留并修正为参数化清单路径，默认 `incoming/snapshot-manifest.json`；恢复工具统一使用 `tools/restore_github_snapshot.py`。

此次只清理当前版本，不重写历史，也不声称 Git 仓库历史体积减少了 120.8 MiB。生成源文件和正式交付内容仍可追溯。

## 数据库状态

现有样本在独立 PostgreSQL/PostGIS 中；原平台全量正式导入继续暂停，等待用户结构审查。本次更新修正仓库入口、样本配置与可复现性，不将原始记录登记、样本图节点或离线预检冒充正式本体采纳。
