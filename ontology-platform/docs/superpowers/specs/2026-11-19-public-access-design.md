# 本体服务器公网访问与迁移方案

日期：2026-11-19。状态：**方案与只读预检，待确认实施**。

本次要求是增加一种通过公网使用或转移服务器的方法，并查清权限、连接问题。现有服务器、数据库及恢复流程保留。本次没有安装连接软件、开公网入口、改防火墙、重启服务或迁移数据。

## 1. 建议与适用范围

建议先增加“**固定 HTTPS 地址 + 登录保护 + 出站隧道 + 现有本机服务器**”。访问端换电脑时只需访问地址，不再为每台访问电脑重建 PostgreSQL、Fuseki 和本体数据。数据库与设备数据继续由同一个服务维护。

这一步是远程访问；原电脑仍负责计算和存储，关机或断网会影响访问。如果目标是让原电脑关机后仍可使用，应采用第 6 节的真正迁移。公网解决传输和访问，新运行主机仍需要安装运行环境，或使用经过验证的系统镜像；一个网址不能代替运行主机。

尚未获得本轮澄清问题的答复，因此这里将“浏览器即可访问、仅授权人员可读写、暂时保留本机”作为**建议假设**，不是用户已经确认的选项。并列保留以下路径：

| 路径 | 适用情况 | 数据是否搬走 | 额外条件 | 建议 |
|---|---|---|---|---|
| Cloudflare Tunnel + Access | 外地电脑直接通过浏览器登录 | 否 | 受控域名、Cloudflare 账户权限、连接器、入口访问策略 | 公网网址主方案；本机 TCP 前置连通检查已通过 |
| Tailscale Serve | 自己/团队已加入同一私有网络 | 否 | 两端加入 tailnet，访问规则与 HTTPS 配置正确 | 本机已有客户端，值得先复用；它是经公网承载的私网访问 |
| 云主机 + 完整恢复 + HTTPS | 原电脑需要关闭，服务长期在线 | 是 | 云主机、管理账号、备份传输和真实恢复验收 | 真正迁移分支，需要额外运行资源 |

Tailscale Serve 面向 tailnet，Funnel 才会把服务开放给互联网。Funnel 不能直接替代登录保护，而且有域名、端口、权限及带宽限制，因此不把“已有 Tailscale”理解为“已具备可安全公开的入口”。[Serve 官方说明](https://tailscale.com/docs/features/tailscale-serve)、[Funnel 官方限制](https://tailscale.com/docs/features/tailscale-funnel)。

路由器端口转发和直接开放本机数据库不列入首选。当前没有路由器管理、运营商入站地址或外网入站验收证据。

## 2. 本机预检与已定位的问题

详细结果、检查层级和未验证条件见[本机预检记录](../../local-server/public-access-preflight-20261119.md)。这些检查是 2026-11-19 新执行的；早期恢复验收另作历史证据。

- HTTP、worker、supervisor、PostgreSQL、Fuseki 均运行；`/health`、`/ready`、`/api/v1/status` 返回 200。当前发布为 `16c6ce16-e28c-5e9c-a766-874fca309c5f`。
- HTTP 绑定 `127.0.0.1:8792`。这适合连接同机出站隧道，其他机器直接访问该机器 IP 的 8792 不会因此可用。
- **域名拒绝已复现**：向本机发送示例公网 Host，返回 `403 HOST_REJECTED`。默认白名单只有本机两个地址。
- **HTTPS Origin 不兼容已通过源码和内存边界检查确认**：现有代码要求 Origin 等于 `http://` + Host。添加 HTTPS 域名后仍会拒绝浏览器同源提交；重写 Host 或补 `X-Forwarded-Proto` 不能修复这个规则。
- GET 没有登录认证；已有 Bearer 仅控制上传。公网入口必须保护整个网站与 API，不能只保护上传页面。
- 初次受限工具环境的出站检查返回 `10013`；沙箱外同样只读检查全部建立 TCP 连接。不能将这个工具权限错误写成 Windows 防火墙或运营商封禁。
- Tailscale 1.104.6 已连接，本机在线且没有 Health 告警；默认 Serve/Funnel 状态为空，网页尚未通过该默认入口转发。本机已选择 exit node，出站探测只证明当前路由下可用，关闭出口后的连通性未测。
- 服务状态报告 `automatic_boot=not-installed`。当前进程在线不代表重启、注销后自动恢复已经验收。

源码位置：[HTTP 边界](../../../local_server/http.py)、[配置校验](../../../local_server/config.py)、[进程管理](../../../local_server/lifecycle.py)。本次确认的是当前环境的障碍；尚无用户先前失败命令和日志，不能断言它们就是此前每次失败的全部原因。

## 3. 公网入口的具体设计

访问路径：

```text
授权用户浏览器
  → 固定 HTTPS 域名
  → Access 登录及人员白名单
  → 经认证的出站 Tunnel
  → 本机 127.0.0.1:8792
  → 已有 API / worker → 本机 PostgreSQL + Fuseki + 发布资产
```

1. 使用一个独立子域名的根路径，页面和 API 同源，例如文档占位 `https://ontology.example.com`。不先挂到 `/project/`，现有前端有绝对路径。
2. **先建立 Access 策略，再发布入口**。默认拒绝，只允许指定使用者；连接器启用 Access token 校验。自动客户端另用入口服务身份，不能把个人登录信息硬编码进脚本。[Access 发布与校验说明](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)。
3. 连接器只转发到 `http://127.0.0.1:8792`。保持 SQL、Fuseki 端口私有，不改成全网监听。隧道是本机主动发起连接，不依赖家用路由器开放入站端口；需验证出站 7844 和相关 DNS/HTTPS。[Tunnel 网络要求](https://developers.cloudflare.com/tunnel/configuration/)。
4. 应用增加显式可信 Origin 列表，只接受所选 HTTPS Origin 和原本机 HTTP Origin；Host 列表增加正式域名，并保留 `127.0.0.1:8792`、`localhost:8792`，否则会破坏启动健康检查。禁止通配 Host、删除 Origin 校验或任意信任客户端转发头。配置字段名和默认迁移逻辑由实施者决定，但旧本机配置必须继续可用。
5. 入口保留正式 Host，或与应用明确约定回源 Host；由真实回源测试验证。Cloudflare 的 `httpHostHeader` 只影响 Host，不能单独解决 Origin。[回源参数](https://developers.cloudflare.com/tunnel/reference/origin-parameters/)。
6. 阅读由入口身份控制；上传继续要求现有应用写 token。第一阶段支持少量指定管理员写入。每人独立写权限、撤销及审计需要后续应用身份体系；不能声称当前共享 token 已实现用户级权限。
7. 应用上传上限目前 64 MiB，要求有效 `Content-Length`，拒绝 `Transfer-Encoding`；代理必须缓冲或正确生成长度。读取 socket 超时默认 15 秒。先用小型合成批次验证，再验收接近上限及慢连接；整库备份走管理传输通道，不走网页上传。
8. 为 API、认证响应及私有导出设置不缓存策略；限制入口请求速率、并发和请求大小。阈值依据小规模实际负载确定，不能把当前 Python `ThreadingHTTPServer` 宣称为已具备公网大并发能力。

连接器可以先以前台方式验证，再安装持续运行方式。Windows 服务安装与服务账户的目录访问权限分别检查；能在个人终端运行并不证明系统服务能读取相同配置。[Windows 服务官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/as-a-service/windows/)。

## 4. 权限分层与稳定运行

| 权限层 | 需要的权限 | 常见错误与处理方向 |
|---|---|---|
| Windows 管理 | 仅安装服务、必要的启动任务和 ACL 时提升 | 非提升终端不能据此完成安装；不把应用长期改成管理员运行 |
| 本机运行账户 | 读取配置、私有凭据、工具；写入指定数据和日志目录 | 个人终端能用、服务启动失败时查账户和目录 ACL；禁止 Everyone 全权限 |
| 网络/入口账户 | 管理域名、Tunnel、Access 或 tailnet 策略 | Windows 管理员不自动拥有云端/组织策略权限 |
| 页面/API | 入口登录 + 应用 Host/Origin；写操作另有 Bearer | 分别记录入口拒绝、403 HOST/ORIGIN、401 写权限，避免混淆 |
| 数据库角色 | 已有 API/worker 专用角色 | 不因网页 403 改 SQL 密码，也不授予公网用户数据库管理员权限 |
| SSH 管理（仅迁移分支） | 正确服务器、用户、公钥与目录 ACL | `timeout`、`refused`、`Permission denied` 按网络、监听、认证分开排查 |

实施时增加可检查的开机启动和失败恢复配置。启动过程为数据库、HTTP/worker、健康检查、入口可用性检查；入口暂时早启动时应明确显示后端不可用并自动恢复。保存有限大小日志，做断网重连和真实重启验收。隧道在线但数据库离线也必须报错。

断电、原电脑关机和所在网络中断仍是这一方案的单点。备份存到独立受控位置并定期校验，不能把隧道或同机第二份文件当作异地备份。

## 5. 复用 Tailscale 的分支

如果访问者愿意安装客户端并加入允许的 tailnet，建议优先复用现有 Tailscale，先确认目标对端、访问策略和 HTTPS 条件，再用 Serve 代理本机 8792。本机已经登录在线，默认 Serve/Funnel 状态为空；仍需确认 tailnet 管理权限。本轮仅查询状态，不运行 `up`、`serve`、`funnel` 来改变配置。

Serve 的 HTTPS 也会遇到第 2 节的 Host/Origin 问题，不能绕过应用修正。接收方只需浏览器和已授权的 Tailscale 连接，不部署数据库。必须验证一台真实外网设备，才能说跨机访问通过。[Serve 访问规则与 HTTPS 前提](https://tailscale.com/docs/features/tailscale-serve)。

当前账号是否可改 tailnet 策略、另一台设备是否获准访问，以管理员控制台和实际访问为准，不能从“本机服务 Running”推断。Serve 与 Funnel 的可见范围不同，不能为排障随手互换。

## 6. 真正迁到公网服务器的分支

只有用户要求原电脑可以退出运行时执行。沿用[已有完整恢复流程](../../local-server/部署与换机.md)，增加加密传输、远端预检和入口切换。优先保持已经验收的组件版本；跨系统迁移另行验收。

1. **远端预检**：确认 OS、CPU/内存、可用磁盘、管理账号、公钥登录、服务器指纹、服务账户目录权限、固定版本工具、空闲端口和下载连通性。容量覆盖恢复后的数据库、备份、解包 staging、索引与增长；在获得当前尺寸和负载后选规格，不凭压缩包大小估算内存或磁盘。
2. **制作当前完整备份**：安排停止写入窗口，停止应用及其他写入者，备份全部必要 SQL 库、全部 RDF 图和资产，必须包含新增 CAD/GIS 的 `cad-imports`。默认从最终备份开始直到新端验收、正式切换完成，源端持续禁写，新端也不接收业务写入；不能备份后恢复源端写入，再直接切到旧快照。若无法接受这一窗口，需要另行设计增量同步与最终追平，本方案不宣称零停机。2026-11-12 的历史备份不能代表 11-16 导入后的最新数据。不要复制活动 PG/TDB 目录。
3. **传输**：由本机发起经校验服务器指纹的 SFTP/SSH 或受控 HTTPS 传输。按文件核验 SHA256 与清单；采用支持续传的传输工具，并另行验证整包完整性。备份含私有原始数据，不能上传到公开 GitHub。公钥通过目标管理渠道安装，私钥不离开管理设备。
4. **新目标恢复**：创建新部署身份和凭据、空 SQL/RDF、资产 staging，执行 `restore → place-restored-assets → start`。不要先 `init` 污染空目标。目标配置、allowlist 和角色必须一致；即使跨机器仍照抄相同 `127.0.0.1:端口/库名` 组合，也会被来源保护拒绝，应按清单选新组合。不要删除保护规则来继续。
5. **验收再切换**：校验完整 SQL 对象/行值、RDF 图/四元组、文件摘要、任务和发布资产路径，再测本体逐级点击、GIS、设备关联、球网、导入/导出及重启。`/ready=200` 只是其中一项。
6. **保持固定入口**：验证新主机后再把同一公网入口指向它。切换期间只允许一套主库接收写入，防止新旧机器数据分叉。旧环境保留为回退；若新环境已接收写入，先核对和保存增量，不能直接切回旧副本丢失新数据。

使用 Windows OpenSSH 时，普通用户和 Administrators 组账号的 authorized_keys 路径与 ACL 规则不同；本机有 ssh 客户端不等于装有 sshd。认证问题依据真实目标账号和服务日志处理，不笼统放宽目录权限。[Microsoft OpenSSH 配置](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)、[公钥认证](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)。

## 7. 实施顺序与验收门槛

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| A：确认入口 | 选择公网浏览器 / 私有团队网络 / 云迁移；明确访问人、域名和管理权限 | 必要资源齐备，原失败命令可对应到权限层 |
| B：应用兼容 | 精确 Host/Origin、本机兼容、代理上传、入口认证配置 | 允许请求通过；恶意 Host/Origin、伪造转发头、无写权限仍拒绝 |
| C：连接验收 | 前台隧道或 Serve，与真实外网客户端联调 | TLS、身份认证、本体导航、地图、球网、分页查询/导出可用；未授权用户被拒绝 |
| D：写入验收 | 指定测试数据和写入账户，小批次及上传边界测试 | 不污染业务批次，写入/任务/发布/查询可回读，上传长度与大小限制正确 |
| E：持续运行 | 启动、重连、日志、备份 | 注销/重启/断网恢复有实际证据，数据库未对公网开放 |
| F：迁移（可选） | 当前完整备份、真实远端恢复、固定入口切换 | SQL/RDF/资产完整回读及单一写入口，回退方案可执行 |

第一轮以少量用户为目标；并发上限和性能目标由小规模实测决定。每项记录“通过 / 失败 / 跳过”，标明源码检查、合成请求、本机实库、真实外网设备与跨机恢复的证据等级。

## 8. 实施前仍需确认

1. 期望是换一台电脑访问现有服务，还是让原电脑退出运行？若只是远程访问，使用者能否安装 Tailscale？
2. 若走浏览器公网入口，已有可管理的域名和 Cloudflare 账户吗？若走云迁移，已有目标服务器吗？
3. 之前失败的具体命令、方式及报错文字是什么？无需提供密码、私钥或 token。

以上会影响实际实施分支。本轮完成的是方案与现有环境检查，公网入口、跨设备访问和真实服务器迁移均尚未验收。
