# 平面 GIS、本体空间标注与球状关系网设计

状态：用户已确认本设计，实施中；新 GIS/RDF 组合发布仍须通过实库与浏览器验收。

## 用户目标与项目边界

用户要求从 `litt1eloser/liangzihu-farm-platform` 找到地图资料和代码，更新现有本体数据库：地图统一为平面，消除重复叠图，在区域内呈现本体对象及设备；增加能用鼠标拖动旋转、观察密集联系的球状本体关系网。

更新目标仍为 `lianggeming14/liangzihu-ontology-traceability/main`，不修改来源仓库、No1dry 总方案或 farm 总库。沿用现有 Python 本地服务器、PostgreSQL/PostGIS、Fuseki/RDF 和本体导航。当前目标代码基线为 `ca3b08200262ed9cb0c578de52e637ae66e1e140`。

原有 180997 实例、178 个概念及历史导航必须保留。495 张表、978 个 RDF 图、28474209 条四元组是上次全库恢复的统计范围；公开导航的五图与这些全库统计不可混淆。2026-11-16 的受限会话只读探测无法连接 8792/25459/23059，这不足以断定宿主服务已停止。本轮尚未独立核验宿主实库状态；实施前先核对进程归属与服务状态，必要时恢复受管服务，再重新建立基线。

## 数据与本体处理

### 完整接收与数据性质

建立独立、不可变、内容寻址的 GIS 批次，不覆盖旧表和旧图。接收每个选定文件的全部表、字段、行、几何、来源声明、质量状态与单位；逐表记录输入/接收/隔离数，不能用主地图筛选数量代替完整接收数量。

保存固定 commit、Git blob、文件 SHA256、路径、源表/行/列、原始属性与几何，保留原件于私有数据目录。对于 GPKG，保存源 CRS 声明与原始几何。未经转换且缺乏坐标依据的原始点、无效面、未确认高程及异常长度进入可查询的质量/隔离目录，不删除也不猜测修复。统计须以实际文件解析为准，不能只照抄来源摘要。

**候选坐标显示政策（本设计选择）：** 已固定来源的登记/参考/锚点及摄像头文件明确提供派生经纬度，可以进入候选规划地图；保存 `display_srid=4326`、`registration_status=candidate_approximate` 与 `original_cad_crs_status=UNKNOWN` 三个不同含义的字段。这表示沿用来源的 EPSG:4547 假设和定位过程，不表示本轮独立确认了原始 CAD 的 CRS 或现场精度。候选图面内的空间计算统一标为派生、待核实，不成为正式业务归属。原始未知 CRS 点不因这一政策被自行假定为 4547 后投影。72/28/39 的主图口径专指上述已转换文件；若逐条解析/几何检查发现问题，应记录隔离及数量差额，不为凑数补造坐标。

GIS 中保存原始/规范几何、源记录、对象身份、位置证据、本体桥和显示派生几何。已有面积等数值按原单位保存；新增几何面积/周长明确标为计算值并记录算法、坐标假设和单位。没有深度数据时保持未知，不把测绘点高程当塘深。

### 对象身份与 RDF

107 个 CAD 对象以固定源命名空间加 CAD 编码建立候选本体实例。67 个农田是图纸土地平整范围，5 个塘口和 35 个设施也沿用草稿/未核实状态，不直接升级为正式资产。

摄像头采用来源文件、源行及记录摘要形成独立候选 ID，`device_iri=null`，不伪造 CAD 登记编码、设备序列号、在线状态或视频入口。28 个设施点明确是文字锚点，不能称为设施实物插入点。

RDF 至少表达候选对象类型、图纸分组、来源、几何证据、位置状态、测量/计算值和质量问题。原始测绘点/几何保留可追溯记录；重要空间对象、设备候选与强关联进入本体实例和关系，而非仅把文件存入 GIS。

已有实体只通过明确 ID/来源映射建立桥。没有可靠 CAD 编码映射时不按名称、最近距离或均分位置合并。点落入某范围可作为带算法证据的空间关系，不自动声明业务隶属；多重命中保留歧义。

## 单一平面地图

采用一个当前平面坐标视图，显示 Z 为 0；原始高程单独保留。当前地图由 72 个田塘主几何、28 个设施锚点、39 个摄像头候选点组成；37 条道路、70 条沟渠可单独开关。默认聚焦田塘和设施/设备候选，道路沟渠不遮挡主图，这是本设计的默认选择。

主几何以登记目录为准；参考层的 67 个重复土地范围只作来源引用，不重复绘制。对所有可显示对象合并计算初始视野，不能只按参考层 bounds 裁掉设施点。来源已记录的异常长线保留质量标记，不通过错误大范围 fit 让主图缩成一点。

不同历史纸面/像素坐标图仍可选择查看，与当前经纬度 CAD 平面互斥，不强行混合坐标系。天地图仅作为可配置的可选底图；没有 Key 或离线时，平面 CAD 范围、对象、设备和比例信息仍能使用。

“不重叠”包含两层验收：

1. 同一对象/几何只生成一个可见要素，选择高亮复用原要素，切版本/图层先清理旧表示。
2. 对田塘面做相交检查。若源面存在真实正面积交叠，原几何与冲突证据保留；显示层派生为互不重叠的平面面片，冲突面片只绘制一次并列出所有涉及对象。不能挪动田块、擅改原边界或伪造唯一归属来让画面好看。数值容差在实施计划中固定并记录，不能以大容差吞掉真实冲突。

地图可平移、缩放、图层筛选和选择区域。点击田块、塘口、设施或摄像头候选，显示本体详情、该区域相关对象、来源和位置状态；可靠关系可继续点击。无位置设备/设施留在同页目录，可直接进入本体详情，但不放猜测点。

地图输出新版本契约，例如 `lzo-spatial-map/2`；旧 `farm-local-map/1` 保持可读。现有 `/ontology/` 地图入口要进入新平面，不能只新增孤立演示页而让主入口仍显示旧图。

## 球状本体关系网

**本设计的默认交互：** 首屏用本体类构成球状布局；鼠标拖动旋转球体、滚轮缩放。点击类先看名称、说明、实例数、相连本体和真实关系，再按需展开下级/实例，沿用既有逐级浏览习惯。用户尚未单独指定点击后的首屏内容，此项为设计默认。

球体是关系布局，不是地球或真实 GIS 位置。节点和边都来自当前发布的本体/RDF，不随机造边营造密集效果。

区分两种边：本体定义中的类层级/对象属性关系，以及由公开业务实例关系聚合的类间联系。Schema 只取 `rdfs:subClassOf` 和 `owl:ObjectProperty` 的 domain/range，datatype-property 的字面量类型不能伪装成另一业务类。每条聚合边保留真实谓词、计数、方向、来源版本；点击可查对应实例关系。

当前导航清单记录 890003 条归一化关系，其中 889893 已解析、110 未解析；这些是历史发布口径，不等于可直接画出的边数或 24054860 个 RDF 三元组。聚合使用明确 `class_iri` 和规范 outgoing 方向，按 `edge_iri` 及 `(subject,predicate,object)` 分别去重；incoming、显式 inverse 和祖先类型展开不再重复累加。未解析关系记录原因而不画假目标。返回发布级白名单 DTO，分别报告唯一关系记录数、唯一三元组数、类对关联次数、未解析数及实际显示数；不得把完整旧明细中的 `provenance.source_record_iri` 顺带暴露给球网。

默认呈现全部公开类及实际联系，允许按类别、谓词和来源筛选。选定节点高亮邻接关系，显示清晰标签；其余边降低透明度。展开实例有明确数量上限、分页与“显示/总计”口径，不把 18 万节点或数百万原文单元格一次塞进浏览器。私有 SourceRecord/原文载荷沿用现有公开 API 保护。

本设计选择沿用轻量原生 JS，使用 Canvas 球面投影、深度排序和轨迹球旋转；地图仍为真实 2D 平面。无需为关系球启动整套 React/Cesium 平台或外部 CDN。具体模块拆分、布局参数、边绘制及拾取算法交由实施计划决定。若现有技术约束要求改选渲染方式，先说明实测依据。

## 接口、导航与发布

沿用 `release_id` 固定读版本，所有地图、关系网、详情与分页必须指向同一发布。

- 地图接口提供当前平面、图层、候选对象/设备、待定位目录、质量状态和数据来源。
- 区域详情以本体 IRI 查询，提供确定关系及带证据的派生空间关系。
- 本体网络接口提供类节点、定义边、观测聚合边、真实总计及按需实例邻域，不开放任意 SQL/SPARQL。
- 网络节点与地图对象共用可追溯 IRI；切换版本清空旧选择和游标，迟到请求不能混入新版本。

现有 CSV worker 按完整独立批次发布，不可将一个小 GIS CSV 上传后替换掉全量本体。新增专用来源准备与组合发布：从当前完整 release 派生，保留旧 schema、五个公开图、全部旧实例/分片和历史 release，加入新 GIS schema、独立 RDF 图、地图与网络读模型。

验证 SQL 全字段/几何回读、新 RDF 完整词项、SHACL、源记录数量、地图与本体双向绑定和导航文件摘要后，最后原子切换 active 指针。失败保留旧 active 及证据。前端必须同时支持旧/新地图契约；部署时核对实际配置的 `review_dir`，不能只改仓库副本而漏掉真实服务使用的 UI。

## 验收与交付

1. 固定源文件完整接收，逐文件/表/字段/行计数可核对；隔离记录未丢失，单位与未知状态可追溯。
2. 67 个重复农田来源映射全保留，但主地图每个只画一次；72 田塘、28 锚点、39 摄像头候选及 7 个无位置设施口径准确。
3. 默认平面没有重复叠图/多高度平面；相交检查与显示面片不重叠测试通过；原始边界没有被覆盖。
4. 已定位与待定位、候选与正式、合成与现场数据分开；不存在假设备坐标/在线状态。
5. 地图点击区域/设施/摄像头可进入对应本体，相关关系可以继续点击；所有公开关联端点存在。
6. 球体实际可拖动旋转、缩放、拾取、筛选与展开；节点/边与 RDF 和聚合总计一致。拖动结束不会误触点击，版本切换无旧响应污染。
7. 旧 SQL/RDF 图与历史版本保持，实库读取和新图/表写入范围有证据；失败不误发布。
8. 真实浏览器检查地图/球网、节点与设备点击、手机布局；PostgreSQL/PostGIS 和 Fuseki 原生验收与离线测试分别记录。不能拿静态 JSON 或 SQLite 替代实库验收。
9. 正常启动服务并更新简单指南。代码、源清单、派生图层、测试、截图、设计/计划及报告同步指定公开 GitHub；原件、活动库、凭据、私有备份和依赖按忽略规则留在本机。
