# 真实竣工图 GIS 数据与接口

用户要求逐项提取五张实际地图，田块和鱼塘作为独立本体实例，为 farm 地图提供数据，并同步公开仓库。用户在来源位置待确认后要求继续；本轮以 farm 中五份原始竣工 PDF 为输入，保留文件 SHA-256。尚未找到所述 upload 目录，不将其路径写成已核实事实。

## 数据与边界

- 基于远端 main `5776ba8d656139d3fb8dfabd137d83dd6dbba11c` 的 ontology-platform，不修改旧 implementation 或覆盖远端新增工作。
- 复核现有 100 田块、20 塘面、22 路渠线、21 标注点的图纸表示。复用 farm 已持久化的真实资料 UUID；不混入 synthetic 演示，不自动合并 E3 或同名清淤塘。
- 保存每图全部原生文字、手工核对的图例、工程量表、尺寸、面积及遗漏清单。文字证据不等于唯一设施；项目汇总表不能重复加总。文字乱码、未识别轮廓字与未描绘背景对象显式列为未完成，不以原图保留冒充语义提取完成。
- 五图坐标均为独立 PDF 纸面 pt，左上原点、x 向右、y 向下。没有 CRS 或控制点时，不生成经纬度、米制轮廓面积、塘深或假高程。
- 图内标注的米、亩等另作带定位与原文的测量陈述。XLS 未标单位的面积维持 unit=null。图纸比例只记录，不能自动作为配准。

## 实现决定

采用新增的图纸 GIS 证据子模块：PostGIS 存储 SRID=0 的纸面几何和原始 JSON，按数据集摘要固定版本，幂等导入。SQLite 仅作离线可复核镜像与开发测试，不能代替 PostGIS 验收。数据包与导入脚本公开，活动数据库不上传。

新 API `/api/v1/drawing-gis` 提供图纸目录、按图/类别/范围分页的要素、单实例、全部标注/工程陈述和完整性状态。使用已有会话及当前权限检查；初版仅全局 internal view 授权可读整批图纸资料，避免把图纸中的 UUID 当作已完成治理对象授权的证明。返回 `DrawingFeaturePage` 而非 RFC7946 GeoJSON；字段明确坐标单位、实体 UUID、图纸表示 ID、数据性质、来源和缺口。现有 `/geometry` 经纬度契约保持不变。

提供可直接运行的离线只读预览和 farm JS 适配器：从原图轮廓构建本地 X/Z 平面、按 UUID/representation_id 定位；不得把五片区任意拼接到卫星底图。不修改 farm 的视觉样式或样例场景。

每个真实田块/塘的 class_iri 和 source identity 保存于证据目录，可供受控摄取复用；这不等于已在生产 Jena 中采纳。生产治理发布仍走现有摄取/审批流程。

## 验收

自动检查来源摘要、100田块覆盖、UUID复用、重复编号隔离、单位、有限坐标、闭合轮廓、分页无遗漏、拒绝错误查询、导入全有全无及重放、跨版本冲突、鉴权失败不泄露数据。PostGIS 实测保存、bbox、SRID、有效性与回滚。逐图复核表和未解决项公开报告；未达到全部文字/背景语义识别时不能宣称无遗漏。

公开仓库仅同步经审查的派生地图数据、代码、契约、复核记录与预览；不复制运行库、凭据、依赖或完整原始运行资产。
