## 尚未完成及原因

- **4 项符号链接测试跳过**：Windows 拒绝当前测试进程创建符号链接（权限不足）。涉及资产子树、配置路径、新环境父目录和快照目标目录。没有用 junction 或模拟结果冒充该系统行为；需取得相应系统权限后重跑。
- **视频解码已补齐**：性能测量结束后在私有测试目录准备项目锁定的 `imageio-ffmpeg==0.6.0`（FFmpeg 7.1），校验发行包 SHA256，真实生成合成 MPEG4 并抽取 JPEG，单项通过；未安装全局工具。
- **旧完整平台的 76 个 integration 测试文件未执行**：本工作树没有专用迁移角色、多库存储、OIDC、S3 及其部署归属配置。其引导测试会写库或重启受管栈，不能把当前轻量业务服务器借作目标。这属于未执行范围，不计入 pytest 跳过，也不以 480 项后端单元通过替代。
- 第二台物理机、跨 OS、Docker 恢复、真实公网/域名访问和高并发容量均未在此次时延测试中验收。

## 本轮修复

1. 原生测试不再使用已成为正式服务的硬编码端口，也不回退读取正式私有环境。新增显式目标清单、DSN 一致性、真实 PG 数据目录和 Fuseki 进程归属校验；每次只创建、清理自己持有的测试数据库和 RDF 图，清理后回读。
2. 修正备份测试对管理员名 `postgres` 的假设和跨实例角色关系准备；仍逐项核对源/目标 grantor 与权限选项。
3. 修复实际复现的 Fuseki 重启问题：旧 PID 被 Windows 复用时不再误判旧进程仍属于本部署；不接管外来进程，保留端口占用及同生命周期身份异常拒绝。正常停止清理未被替换的记录。多个控制器仍须顺序启停。
4. 仓库检查明确区分可选的旧静态关系网快照与必需资产；必需地图、manifest、150 个分片及内容校验仍保留。旧静态关系网文件缺失被如实报告，不伪造数据补位。
5. 首次性能校准的四次导出因基准校验器对普通字符串和 `xsd:string` 的比较不一致而失败。只读核对原始 NT 与 Fuseki 均有 447 条、17 处差异均属同义字符串；修正基准规范化后，用新实例重新校准通过。数字词法、精度、类型和语言差异继续严格验证；失败校准没有混入成功时延。

CSV 初次单测的一个失败来自临时目录放错位置，恢复测试前提后 88 项完整通过；后端初次三个缺包失败，改用全部 95 项依赖匹配锁文件的现有隔离环境后 480 项完整通过。上述重跑没有修改正式依赖。

## 性能环境与口径

Windows 11，14 个物理核心 / 20 个逻辑 CPU，31.85 GiB 内存；Python 3.12.7、PostgreSQL 17.11、Java 21.0.7、Fuseki 6.2.0。轻量服务使用 psycopg 3.2.12；另一个 implementation 回归按其锁文件使用 3.3.6，二者没有混装。正式服务仍在后台运行；没有与本轮实库回归同时计时。

测量使用新建实例、一个真实 worker、回环 HTTP 和明确标记的合成 CSV ZIP。规模为 100/1000/5000 个塘口，各含一个农场及完整归属关系。每档首遍一次、不同内容重复三次，不命中导入去重。首遍未清空 OS 缓存，不称为严格冷启动。
