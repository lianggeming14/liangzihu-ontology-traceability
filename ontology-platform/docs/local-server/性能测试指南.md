# 导入、查询、发布和导出时延

基准脚本为 `scripts/bench_local_server.py`。它新建独立 PostgreSQL/Fuseki 实例，在回环 HTTP 服务上上传合成 CSV ZIP，由真实 worker 完成 SQL/RDF 回读、SHACL、发布和导出。不会加载默认业务配置。实测结果见[本轮回归与性能报告](python-regression-performance-20261124.md)。

## 准备与运行

在 `ontology-platform` 目录执行，先按[部署与换机](部署与换机.md)准备本地依赖与匹配版本的原生工具。工具路径按实际位置替换。测试数据目录必须全新，不允许复用已有运行结果；默认端口为 HTTP 8894、PostgreSQL 26559、Fuseki 24159，必须空闲。

```powershell
.\.venv-local-server\Scripts\python.exe scripts\bench_local_server.py `
  --data-dir .runtime\benchmark-new-run `
  --pg-bin .tools\local-server\postgresql-17.11\bin `
  --java-home .tools\local-server\java-21 `
  --fuseki-home .tools\local-server\fuseki-6.2.0
```

默认规模为 100、1000、5000 个塘口，各关联一个农场；这些是明确标记的合成数据，不是真实生产塘口分配。每规模首遍一次、不同内容重复三次。每规模固定最后的发布版本，实例/详情查询各 20 次，JSON 完整分页导出 20 次，CSV/RDF 各一次。所有数据保留在私有 `.runtime`，不会自动清空。

第一次运行建议先用另一个全新目录，加 `--sizes 5 --warm-repeats 0 --query-repeats 2 --export-repeats 2 --page-size 10` 校准流程。校准结果不能和正式矩阵合并。`--prepare-only` 只创建并停止目标；之后通过 `--config <新目录>/config.json` 运行该未使用目标，仍需传入本次所需规模参数。已使用的标记不会被再次运行。

不要与实库回归、全库导入或备份同时计时。停止或降低其他负载前应确认其用途；脚本不停止既有正式服务。当前机器中存在的后台服务要写入 `--background-note`。

## 指标口径

| 指标 | 实际计时边界 |
|---|---|
| 上传登记 | HTTP POST 开始至 202 返回；不等于导入完成 |
| 排队 | 提交任务返回至 worker 领取返回，包含领取 SQL 时间 |
| 导入处理 | 领取返回至 SQL 和 RDF 均写入并完成回读；不含后续发布 |
| 发布 | 导航/SHACL 构建开始至登记、文件验证和发布激活完成 |
| 原子激活 | `publish_release` 完整 SQL 调用，包含连接、锁、状态更新和提交 |
| 上传到完成 | HTTP POST 开始至任务完成；随后另验 HTTP 可见发布版本 |
| 查询 | 真实 HTTP 请求及响应解析，固定发布版本；实例页与对象详情分开统计 |
| 导出 | 完整塘口类型的全部分页；包括 HTTP、解析和正确性核对，另存纯 HTTP 累计时间 |

导出不是“整个服务器全库备份”：只导出该发布塘口类型的公开业务三元组，过滤规则与公开 API 一致。报告保存页数、字节数、对象数、三元组数及独立 RDF 指纹，JSON/CSV/RDF 都要匹配。不能用第一页响应时间代替完整导出时延。

首遍没有清空操作系统缓存，不能称为严格冷启动。重复导入每次使用不同内容，避免内容去重使结果虚假变快。p50 为中位数，p95 为 nearest-rank；失败独立保留，不计入成功样本百分位。三次重复导入和单次 CSV/RDF 的样本较少，无法据此推算高并发容量或服务等级。

## 结果和失败

结果默认为测试目录的 `benchmark-results.json`；`status`、逐项失败数、未执行规模和 `cleanup` 一起查看，不能只摘成功时延。失败诊断在同目录 `benchmark-diagnostics.log`，属于私有日志，不应原样上传。

程序要求实例归属、SQL 实际数据目录和空数据库匹配，拒绝本机正式/旧源端口与间接 libpq 重定向变量。配置或权限错误应修正独立测试配置，不能关闭保护或把正式凭据填进去。服务启停由一个控制器顺序操作；当前生命周期接口不承诺多个控制器并发启停安全。

性能证据属于当前机器、真实 PostgreSQL/Fuseki、合成 CSV 管线；不替代 CAD 导入、18 万实例生产全量、高并发、跨机网络或完整业务平台的验收。
