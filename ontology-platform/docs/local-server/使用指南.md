# 梁子湖本地本体服务器：使用指南

本服务默认只在这台电脑上访问。已导入数据、原文件、任务进度和历史版本保存在私有数据目录；源代码可以同步 GitHub，私有数据与凭据不上传。数据仍保留“来源导入、尚未现场确认”的性质。

本版 HTTP 与原生监管使用 IPv4；`::1` 等 IPv6 bind 会在配置检查时明确拒绝。默认地址为 `127.0.0.1`。

## 日常启动与停止

在 `ontology-platform` 目录中，双击 `infra/local-server/local-server.cmd`，等待启动结果后打开浏览器。默认地址：

**http://127.0.0.1:8792/**

也可以在此目录打开 PowerShell：

```powershell
.\infra\local-server\local-server.cmd start
.\infra\local-server\local-server.cmd status
.\infra\local-server\local-server.cmd restart
.\infra\local-server\local-server.cmd stop
```

`start` 启动本部署的 PostgreSQL、Fuseki、HTTP 与导入 worker；重复执行不会重复初始化或导入。`stop` 按相反顺序关闭服务，保留数据。请等待命令结束后再关机或复制文件。这里没有安装 Windows 开机启动任务；电脑重启后重新运行 `start`。

`status` 的 `processes` 应全为 `true`，受管数据库应显示 `running`。浏览器状态页显示当前发布版本与导入任务。`/health` 只确认 HTTP 存活，`/ready` 额外确认当前版本的 RDF 图可读；它们不代替完整数据验收。

如果地址或端口被调整，以 `status` 返回的 `url` 为准。PowerShell 入口支持 `-Config` 指定配置；CMD/Linux 入口支持环境变量 `LZO_LOCAL_CONFIG`。

## 本机地址、远程访问与换机

`127.0.0.1` 指打开浏览器的那台电脑。服务器搬到另一台机器后，在新服务器本机仍可打开 `http://127.0.0.1:8792/`。从你的电脑访问新服务器时，可在已有 SSH 连接条件下建立隧道：

```bash
ssh -N -L 8792:127.0.0.1:8792 用户名@新服务器地址
```

保持该连接，再在你的电脑打开 `http://127.0.0.1:8792/`；此时浏览器通过隧道访问新服务器的服务。该方式保留服务的本机绑定。SSH 服务、账号和跨机网络需在目标环境准备；本轮未执行第二台物理机器或 SSH 隧道验收。

2026-11-19 只读检查确认当前 Windows 电脑有 SSH 客户端，但没有注册的 `sshd` 服务，默认 22 端口无监听。如果另一台电脑要连接这里，需要先准备 SSH 服务端；如果这里连接另一台服务器，则应检查远端。当前本机 8792 已占用，不能同时用它建立另一个客户端转发监听。完整方向说明、备用端口的 Host 配置、错误对照和 HTTPS 公网方案见 [SSH 连接排查与 HTTPS 入口详解](ssh-and-https-access.md)。

换机按[部署与换机](部署与换机.md)执行完整备份、新环境初始化、SQL/RDF 与业务资产恢复、路径配置和回读核验。本体 URI、业务 ID 与 RDF 关系随备份保留。新机按实际情况配置 `root`、`data_dir`、工具位置、端口和新凭据。其他脚本中的 `$RUN_ROOT/natural100` 这类路径也属于执行命令的机器，需要迁移对应文件并在目标机重新设置变量；本项目的服务路径由私有 JSON 配置管理。

## 导入文件

1. 打开首页“导入完整批次”。选择 UTF-8 CSV，或仅包含 CSV 的 ZIP。
2. CSV 文件名就是逻辑表名，例如 `ponds.csv`；使用小写字母、数字与下划线，表头必须包含唯一的 `id` 列。不要把文件随意改名为 `source.csv`。
3. 在本机打开 `.runtime/local-server/private.env`，复制 `LZO_LOCAL_WRITE_TOKEN=` 后面的值（若有外层引号，仅复制引号内的内容），填入网页“本机写入凭据”。不要将凭据发到聊天、截图或 GitHub。网页不把它写进源码或浏览器持久存储，登记成功后清空输入框。
4. 点击“上传并登记任务”。先返回任务编号，再由后台依次校验、写入 SQL、生成 RDF、回读、验证与发布。可持续查看状态与失败阶段。

同一内容、同一逻辑表及同一映射重复提交会复用任务。不同 CSV 文件名代表不同逻辑表，因此可产生不同任务。导入失败时，旧的已发布版本继续可读；修正文件后重新提交。当前版按完整批次快照发布，不执行按 ID 的跨批次自动合并或在线任意编辑。

若是已排除的临时服务故障，可由管理员运行 `local-server.cmd retry-job <任务ID>` 重新排队失败任务；这个操作使用本机专用 worker 凭据，不开放任意数据库写入接口。

默认上传上限为 64 MiB。若需要提高限制，先确认空间足够，再调整私有 JSON 配置中的 `limits`。解压、行数与 ZIP 路径另有服务端限制；不要仅改浏览器代码。

## 查本体、实例、属性和关系

首页“查询与导出”先选择“浏览版本（固定）”，再选择类型查看实例，点击实例查看公开属性、正向关系与反向关系；关系支持继续点击和分页。每次请求固定一个 `release_id`，游标也绑定该版本，不会把两个版本的分页混在一起。页面提供完整发布历史；也可以收藏 `/?release_id=<版本ID>`。

导入产生新 active 版本时，页面提示“当前已发布新版本”，不会自动替换正在浏览的历史内容。点击“切换到当前发布”或手动换版本，会立即清空旧实例/属性、类型选择与游标；旧请求的迟到响应不能重新填回新版本。打开本体浏览器的链接同样带着当前所选版本，因此仍可回看旧 GIS 图层。

“打开本体浏览器”进入分类树、空间地图与本体关系球。新版 CAD 地图采用来源转换的候选经纬度，在一个平面显示田块、塘口、设施文字锚点和摄像头图纸标记；原始 CAD 坐标参考仍未确认。点击图形或目录对象可查看面积、周长、来源、空间关联，并继续进入本体实例与关系。道路、沟渠可单独开启；“查看历史图纸”保留旧图像像素或图纸点坐标地图，两种坐标视图分开显示。

摄像头图标表示 CAD 位置候选，不代表设备已联网。没有坐标的设备保留在“只看待定位”目录；未知深度保持“未提供”。面积、周长、长度的计算值有单位与算法说明，不能当作现场实测。重叠面片只绘制一次，点击会列出所有相关对象。

“本体关系球”支持拖动旋转、滚轮缩放、键盘方向键旋转。先选择节点查看相连关系，再进入下级类型或实例；选择关系可逐页查看具体对象。连线分别表示本体定义与实际实例关系聚合，演示分配保留合成性质。旧版本未生成关系网时会明确提示，可继续使用本体目录。

API 示例（类型 IRI 通过 `/api/v1/manifest` 获取，按 URL 编码）：

```text
GET /api/v1/status
GET /api/v1/manifest?release_id=<版本ID>
GET /api/v1/children?release_id=<版本ID>&parent=<本体IRI>
GET /api/v1/instances?release_id=<版本ID>&class=<类型IRI>&limit=30
GET /api/v1/resource?release_id=<版本ID>&iri=<实例IRI>
GET /api/v1/maps?release_id=<版本ID>
GET /api/v1/network?release_id=<版本ID>
GET /api/v1/network-relations?release_id=<版本ID>&source=<来源类型IRI>&predicate=<关系IRI>&target=<目标类型IRI>&limit=12
GET /api/v1/jobs/<任务ID>
GET /api/v1/releases
GET /api/v1/releases/<版本ID>
```

这些接口只读公开业务对象。来源物理行、原始 payload、任意 SQL/SPARQL 管理命令均不通过它们开放。

## 更新已审查的 CAD 空间数据

GIS 更新使用专门的组合发布入口，会保留当前完整本体数据。不要通过普通 CSV 上传入口提交一份小 GIS 表来替换整个版本。在项目根目录执行：

```powershell
.\.venv-local-server\Scripts\python.exe scripts\download_cad_sources.py --manifest docs\local-server\gis-source-audit-2026-11-16.json --destination .runtime\cad-gis\inputs
.\.venv-local-server\Scripts\python.exe scripts\prepare_cad_gis.py --inputs-dir .runtime\cad-gis\inputs --output-dir .runtime\cad-gis\prepared
.\.venv-local-server\Scripts\python.exe scripts\import_cad_gis.py --config .runtime\local-server\config.json --bundle .runtime\cad-gis\prepared\bundle.json
```

第一步下载固定提交并核对 Git blob、字节数和 SHA256；第二步保留全部来源记录并生成候选对象、测量和显示几何；第三步在新 SQL schema 和 RDF 图中写入、回读校验，合并完整历史导航后切换发布版本。配置会自动读取其私有环境文件，不需要在命令行写密码。不同来源批次必须使用不同准备目录，避免覆盖既有批次。

发布失败时继续使用旧 active 版本。当前 CAD 写入保护限定已审查本机部署的 PostgreSQL 25459、Fuseki 23059，并禁止写迁移源；变更部署端口时需要同步审查导入器的目标保护。更新依赖请使用 `infra/local-server/setup.ps1`（Linux 使用 `setup.sh`），其中固定了几何计算依赖。

换机时应备份全部数据库、全部 RDF 图、所有发布目录，以及本次 CAD 导入保存的私有来源资产。仅复制 GitHub 项目代码无法恢复这些数据；具体步骤继续按 [部署与换机](部署与换机.md) 执行。

## 导出

选择类型和 JSON、CSV 或 RDF 格式，点击“下载完整公开类型数据”。浏览器固定版本并逐页下载公开规范三元组（实例、属性、关系）；CSV 保留对象类型、datatype 与语言列，RDF 输出 Turtle。浏览器导出上限为 128 MiB，超过时选择更具体的类型。CSV 为防公式执行，对危险起始字符加单引号；需要精确 RDF 词法值时使用 JSON/RDF。

程序可调用 `/api/v1/export?release_id=...&class=...&format=json|csv|rdf&limit=1000`。JSON 的 `next_cursor` 或 CSV/RDF 响应头 `X-Next-Cursor` 非空时继续请求，直到为空。不要只保存第一页而称为完整导出。

完整来源数据、所有 SQL schema、默认图及全部命名图使用下面的私有备份流程保存。

## 备份与校验

管理员先准备私有备份选项 JSON：枚举完整 SQL 数据库、完整 RDF dataset、原文件与导航资产。参考 [部署与换机](部署与换机.md)；不要只选当前 SQL schema，也不要把整个活动数据库目录当作资产复制。

在 PowerShell 中：

```powershell
.\infra\local-server\local-server.cmd stop
.\infra\local-server\local-server.cmd backup backups\backup-2026-11-12 --options .runtime\local-server\backup-options.json --writers-stopped
.\infra\local-server\local-server.cmd verify-backup backups\backup-2026-11-12\manifest.json
.\infra\local-server\local-server.cmd start
```

备份期间 HTTP 与 worker 保持停止。命令会临时启动受管数据库进行逻辑归档和完整 RDF 导出，完成后正常关闭它们；外部服务模式由管理员保证源端其它写入者也已停止。只有实际确认全部源写入停止后才使用 `--writers-stopped`。

目标备份目录必须新建或为空；空间不足、缺少资产或校验失败都会停止并保留失败证据。完成标记是清单 `status=complete`；校验命令必须返回 `status=verified`。凭据、授权密钥单独私有保存，不在备份内。

这里的 `backups/...` 是从项目根运行命令时的本机相对路径示例，不要求存在 D 盘。备份、恢复 staging、业务数据和工具目录均可在私有配置中调整；备份与原件目录必须受忽略规则保护，不能因为改了位置进入 GitHub。

## 恢复、换机

恢复必须使用新的 SQL 空数据库、新的 RDF 空 dataset 和新的资产目录，连接地址不得指回源端。不要直接运行恢复覆盖当前服务。

```powershell
.\infra\local-server\local-server.cmd stop
.\infra\local-server\local-server.cmd restore backups\backup-2026-11-12\manifest.json --options .runtime\local-server\restore-options.json
.\infra\local-server\local-server.cmd place-restored-assets backups\backup-2026-11-12\manifest.json --options .runtime\local-server\restore-options.json
```

新机先安装匹配版本工具、准备新账户与空目标、创建新部署身份，再执行恢复。完整步骤和路径对齐规则见 [部署与换机](部署与换机.md)。恢复必须返回 `restored_verified`，资产对齐必须返回 `assets_placed_verified`；随后核对全部 SQL 库/schema、完整 RDF 清单、任务与发布元数据和导航文件，再启动。

新环境准备统一使用 `scripts/provision_local_server.py`，不手工复制旧身份或 PID。首次恢复的 SQL/RDF 内部端口要与备份源身份组合不同，例如新目标 25479/23079，HTTP 仍为 8792；详细命令见部署指南。

`asset_destination` 是新的空 staging，例如 `.runtime/local-server/restored-assets`，不能直接使用已装有身份/PG/TDB 的 `data_dir`。对齐命令按显式 `asset_placement` 将已校验业务目录复制到正确位置，保留 staging，不更换 `data_dir` 或部署身份；遇到符号链接、原生文件、非空冲突或摘要不符会失败。恢复/对齐未完成时会阻止 `start`、`serve` 和 worker，保持服务停止；不要删除 pending 标记来跳过校验。原始源环境留作回退，失败时不要删除它。

## 常见状态

公网访问与密码排错请先读[连接、密码与权限复核](connection-auth-audit-20261124.md)和[固定 HTTPS 域名手册](https-domain-setup.md)。两者记录了待补条件与实际检查边界，不表示公网入口已经部署。

| 状态或错误 | 处理 |
|---|---|
| `awaiting_release` | 尚未发布版本；导入新批次，或由管理员验证后登记初始快照。 |
| `HOST_REJECTED` / `ORIGIN_REJECTED` | 从 `status.url` 的本机地址打开；不要通过未知域名或跨站页面提交。 |
| `DISK_LIMIT` | 释放或迁移私有数据存储后重试，不要删除未核对的原库。 |
| `DEPLOYMENT_OWNERSHIP_REQUIRED` | 目录移动后按换机流程验证新归属，不能照抄旧 PID 文件。 |
| `FUSEKI_LEGACY_STOP_REQUIRED` | 已有 Fuseki 用旧方式启动，需要管理员正常关闭后用本入口启动一次。 |
| `ASSET_PLACEMENT_REQUIRED` | 先完成已验证 staging 的 `place-restored-assets`；检查私有报告，不能绕过标记启动。 |
| 任务失败 | 记录任务编号与阶段，修正文件/配置；错误响应不包含原始敏感数据。 |

日志位于私有运行目录的 `http.log`、`worker.log` 与数据库运行日志。HTTP/worker 日志轮转；不要把私有日志原样公开。真实实库、容器、跨系统与现场验收的通过/失败/未执行状态以本次交付验收报告为准。
