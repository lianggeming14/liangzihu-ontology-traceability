# 工程与仿真复现说明

## 只核对清单

需要 Python 3.10 或以上版本。将固定来源包的 `csv/` 解压到一个新目录。从本说明所在目录运行下列命令，把输入路径替换为解压得到的路径。计数器使用 Python 标准库，按原始字节核对 SHA-256，按 CSV 逻辑记录核对表头与行数。文件缺失、多出、摘要变化或列宽不符均会使核查中止。[固定来源包](https://github.com/lianggeming14/upload-files/blob/cb9353499b6ede33fa60b3c67e18a983e362ab16/csv.zip)

```powershell
python verify_simulation.py --csv-dir "D:/B3复现/csv" --source-manifest "仿真复现记录/source-manifest.json" --table-roles "仿真复现记录/table_roles.json" --out "复算清单.csv"
```

预期结果为 66 张表、153,862 条记录、1,397 个表头列次、604 个不同列名和 3,539,134 个数据单元格位置。可将输出与 `02_工程与数据/66表仿真清单.csv` 按表名、行数、列数和 SHA-256 对比。

## 从种子重新生成数据

`DB_READY_生成脚本/` 内的 12 个 Python 文件逐字节取自原数据工程 `output/db_ready/scripts/`，涵盖业务与环境生成、集成、数据库写入、质量检查、独立校验及配套单元测试。本次复现使用 Windows 11、Python 3.12.7、SQLite 3.45.3 和 Python 标准库。SQLite 需要支持 STRICT 表。版本 `DB-READY-1.0.0` 和种子 `20251031` 固定在生成器中；完整脚本的 SHA-256 见复现摘要。

取得团队保留的原输入，在独立数据工程根目录保持下列结构。生成器会读取固定天气、附件来源清单、原模式、审阅依据、归一化的六种资产目录、角色定义并复制原资产，以便复核来源与文件引用。关键输入 SHA-256 见 `仿真复现记录/source_inputs.json`。所需原始资产含第三方样例，依原项目的访问范围留存。

```text
独立数据工程/
  数据审阅意见.md
  output/
    assets/
    public_sources/
    scenario/
    schemas/
    l2_cleaned/
      normalized/
      scripts/roles.json
```

在本说明所在目录运行，将 `$dataProject` 指向已准备输入的独立目录。选用尚不存在的输出名称以保留旧版。原生成器要求输出位于该工程的 `output/` 内，且目录名以 `db_ready` 开头。

```powershell
$dataProject = "D:/B3复现/独立数据工程"
$rebuilt = Join-Path $dataProject "output/db_ready_b3_check"
python DB_READY_生成脚本/build_ready.py --project-root $dataProject --output-root $rebuilt
python DB_READY_生成脚本/verify_ready.py --directory $rebuilt
python verify_simulation.py --csv-dir "$rebuilt/csv" --source-manifest "仿真复现记录/source-manifest.json" --table-roles "仿真复现记录/table_roles.json"
```

2026 年 11 月 24 日已在独立输入副本完成上述生成、SQLite 校验、全量哈希比对。生成器退出码为 0，复验器退出码为 0。119 项业务检查通过，剩余问题 0，SQLite 外键错误 0，66 张表的 CSV 与 SQLite 行数差异 0。重新生成的 66 个文件与保留版及平台源清单逐字节一致。[本次复现摘要](仿真复现记录/reproduction_summary.json) · [CSV 与 SQLite 核验详情](仿真复现记录/rebuilt_csv_sqlite_verification.json)
