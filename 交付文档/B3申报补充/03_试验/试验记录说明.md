## 复现

先从 Git 导出完整 9ded 提交到临时目录。下面的 `FROZEN` 指其中的 `ontology-platform` 路径，`ARCHIVE` 指上述 SHA-256 的原 ZIP；`TOOLS` 指工程的 `.tools/local-server` 目录。`PYTHON` 应指向本地服务器锁定依赖的解释器。各脚本的 `--help` 提供参数；私有运行目录每次使用新名称，活动数据库、原始行和自动生成凭据仅落在 `.runtime`。

1. 冻结 Python 在 `FROZEN` 目录运行 `python -m pytest -q -rs tests/local_server --ignore=tests/local_server/test_store.py -p no:cacheprovider`。以环境变量 `LZO_LOCAL_NODE_EXE` 指向 Node；`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`。JS 从同目录用 `node --test` 显式传入 `docs/fish/ontology-review/` 下四个 `.test.mjs` 文件。
2. `python retest_full_csv.py --frozen-root FROZEN --archive ARCHIVE --pg-bin TOOLS/postgresql-17.11/bin --private-run FROZEN/.runtime/source-intake-new --output 来源层新结果.json` 复现独立 Store 测试及三次来源层写入。
3. `python retest_reviewed_sql.py --frozen-root FROZEN --archive ARCHIVE --pg-bin TOOLS/postgresql-17.11/bin --run-name official-sql-new --output 整批66表正式SQL导入原始记录.json` 复现专用 SQL 导入。冻结程序要求 `127.0.0.1:25449`、指定库名和角色，脚本先验证端口可独占绑定，再创建新集群并核对目录，端口已被占用时退出。
4. `python retest_http_intake.py --frozen-root FROZEN --archive ARCHIVE --tools TOOLS --run-name http-intake-new --output 整批66表应用入口逐次输出.json` 复现通用入口。
5. 在 fbb9 工程的 `ontology-platform` 内运行原脚本 `scripts/bench_local_server.py`，按原指南提供全新 `--data-dir`、`--pg-bin`、`--java-home` 和 `--fuseki-home`，加上 `--sizes 100 --warm-repeats 3 --query-repeats 3 --export-repeats 3 --format-repeats 1 --page-size 1000`。基准使用单 worker，完成后停止本轮实例。用安装 Matplotlib 和中文字体的 Python 执行 `generate_trial_tables.py`，读取本目录 JSON 原记录以重建汇总表和曲线。[工程基准指南](https://github.com/lianggeming14/liangzihu-ontology-traceability/blob/fbb9fbbc556f74c7873bc1f6b39d381f43b4e66e/ontology-platform/docs/local-server/%E6%80%A7%E8%83%BD%E6%B5%8B%E8%AF%95%E6%8C%87%E5%8D%97.md)
