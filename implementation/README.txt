本地工程版交付说明
更新日期：2026 年 10 月 11 日

一、这次交付是什么

这是可运行、可持久化的本地工程原型，包含本体与证据数据服务、多维关系网络、产品批次溯源和浏览器界面。当前默认数据库为 SQLite，数据保存在 implementation/data/agri.db；同时提供 PostgreSQL 模式迁移、适配器和独立测试入口。

代码由当前模型继续实现。用户已明确停用 Kimi；当前系统运行不需要 Kimi，也不需要重新登录 Kimi。KIMI_TASK_*、run_kimi_isolated.py 和 kimi-* 日志仅为早期尝试历史，详见 LEGACY_KIMI.txt。

演示记录均为 synthetic 合成数据。该工程没有接入真实梁子湖生产平台、真实设备或外部溯源平台，也没有完成生产部署和农场现场验收。现有平台的生产、库存、质量及权限服务仍需另行适配，不能把演示库存账接入真实业务后同时维护两套权威库存。

二、启动与停止

工作目录：
  C:\Users\robot\Desktop\ontology\implementation

现有机器推荐入口：
  双击“启动系统.cmd”

该脚本使用：
  C:\ProgramData\anaconda3\python.exe -X utf8 run_server.py --open-browser

也可以在上述工作目录打开终端，运行：
  C:\ProgramData\anaconda3\python.exe -X utf8 run_server.py

默认地址：
  http://127.0.0.1:8787/

程序仅绑定本机回环地址。启动后会执行迁移、幂等加载合成示例，并尝试打开浏览器；在启动终端按 Ctrl+C 停止。数据库会保留，重新启动不会清空现有记录。不要通过删除数据库来解决已有迁移校验不一致；已有数据变更应创建新迁移并验证恢复。

常用参数：
  --port 8788          使用其他本地端口
  --no-seed            不自动载入合成示例
  --no-demo-login      禁用本机演示角色登录
  --open-browser      启动时打开浏览器

迁移到其他电脑时，需要 Python 和 requirements.txt 中的依赖，并调整启动脚本里的 Python 路径。当前脚本使用 Flask 本地开发服务器，不是生产服务器部署方案。

当前受控执行环境的 socket 权限限制尚未解除，因此本次没有完成持续端口监听、外部 HTTP 连接或公网访问验证。浏览器验证已通过真实 Flask 请求桥接执行，详见下文“验证范围”。这一区别不影响源码、持久化数据和界面交付，但启动端口仍需在用户正常终端环境确认。

三、界面与现有功能

工作台提供对象库、多维关系图、生产与物料批次、证据材料、治理及产品溯源等视图；可新增对象、查看详情、查询事件和证据、执行有权限的审核及发布操作。

本轮已落地的核心能力包括：
  1. 稳定对象身份与语义分类分离，领域包按命名空间和版本登记。
  2. 稻虾、蔬菜、禽蛋等合成领域示例；新增品类可通过领域包及类型定义接入，不依赖水稻专用页面分支。
  3. 对象、限定关系、观测、断言、原始证据、事件参与角色、动态或快照对象集。
  4. 空间、生产、物料、事件、证据、观测和断言的多维网络；支持中心对象、维度、深度和预算。
  5. 生产周期与物料批次分开；采收、拆批、并批、加工及损耗、包装、发货、部分签收。
  6. 数量使用十进制字符串和 Decimal 运算，拒绝不相容单位及超额耗用，不以浮点数进行物料平衡。
  7. 事务幂等、租户范围检查、角色授权、审计记录、事务 outbox 与有序增量查询。
  8. EvidenceBundle 与 TraceabilityBundle 分开，内部证据查询与公开白名单数据分开。
  9. 审核发布、公开随机码、真实 SVG 二维码、证据撤回及批次召回后的公开状态失效。
 10. 版本化图交换配置的 JSON-LD 和 Turtle 导出；提供该项目固定 JSON-LD 配置的内存往返校验，不是任意 RDF 的通用无损转换或直接业务回写。
 11. 原始文件上传、内容哈希、按租户隔离存放和授权下载；下载时检查原件完整性。

图查询中的事件、证据、观测、断言和限定关系是不同种类的节点。证据指向一条限定关系时，会落到独立关系节点，不意味着证据支持该主体的所有说法。物料祖先只由投入产出表产生，空间共存、包装容纳或共作关系不会自动变成物料谱系。

图查询可能返回 truncated=true 及 gaps；这表示预算、深度、大字段或引用范围造成缺口。客户端必须展示这些状态，不能把截断结果宣称为完整知识网络。多维图当前提供当前记录视图，不接受 valid_at、known_at 或 revision 历史重建请求。

  GET /api/v1/public/trace/{code}

具体方法、请求字段、响应和约束，以 OpenAPI、contracts/input-schemas.json 及服务实现为准。不要把列表的第一页当作全部数据；普通列表遵循其分页字段，增量 changes 接口使用专用 cursor。图查询使用显式预算和截断状态。

受保护请求使用：
  Authorization: Bearer <从受控本地配置获取的令牌>

写请求必须携带 Idempotency-Key。同一租户、同一键和相同请求重放会返回原结果；改变已成功请求的载荷会产生冲突。重试不是新的业务操作，不应随意更换键。

批量接入按记录分别提交，不是整批原子事务。一个批次允许部分成功：
  - 重试同一表单时保留原 base key、记录顺序及已成功记录的原载荷。
  - 只修正失败条，保持其原索引；后端按“base key:索引”处理。
  - 已成功条返回原记录，不再重复写入；失败条修正后可提交。
  - 整理顺序、删除条目或开始新业务批次前，应明确创建新批次，不要复用有歧义的索引键。
  - accepted_count 表示本次回执接受条数，其中可以包含幂等重放，不等于新增数据库行数。

传感器、天气、图像、视频、遥感、文档、手工填报和官方 API 已有信源类别及标准记录入口。当前接入的是文件和已结构化的观测、断言、预测或事件；尚未实现摄像头流采集、视频解码、OCR、视觉识别、遥感反演、天气供应商同步或生产模型自动调度。视觉和遥感结果不会被当作直接实测；预测进入断言而不是实测观测。原始证据缺失时不自动编造可信依据。

五、权限和本机演示模式

默认启动会生成 data/api-tokens.json，令牌映射到固定身份、租户和角色。令牌是访问凭证，不应粘贴到公开资料、前端代码、日志或版本库。修改受控配置后需重启进程生效；当前没有生产级令牌签发、到期轮换或统一登录系统。

默认演示模式允许本机用户选择演示管理员、操作员、审核员或查看者，用于体验工作流。它不证明操作者的真实身份；能够访问本机环境的人可能取得演示管理员能力。需要受控使用时，应启用 --no-demo-login，并通过受控 API 身份访问。

后端依据已认证身份确定租户，客户端传入 X-Tenant-ID 不会授予另一个租户的权限。服务有角色检查、Host 白名单、写请求来源检查、HttpOnly/SameSite 会话配置和公开数据白名单。当前权限模型主要是租户与角色范围，尚未对接现有平台的组织体系、对象级授权和完整监管分级授权。

不要将当前 Flask 开发入口、演示登录或本地管理员令牌直接暴露到公网。正式部署需独立配置生产服务进程、HTTPS、允许域名、身份体系、最小权限数据库账号及运行监控。

六、五个重点的实现边界

概念与身份：
  已有稳定 UUID、身份类型、版本化语义类型赋值和领域包。不同领域可以共享同一实体身份。
  尚未完成大规模同名消歧、自动实体合并、全量外部本体映射、独立的完整 Property 属性字典和领域包升级迁移治理。

关系语义：
  已有类型端点校验、方向、限定属性、适用时段、证据关联、事件角色和物料谱系。
  图路径表示已登记的结构关联，不自动证明因果、同时成立或质量合格。新业务规则仍需代码、契约和测试支持。

时空与事件：
  已有明确时间字段、关系有效区间、事件时间、参与者以及生产/物料不同周期。
  尚未实现完整双时态快照、统一历史切片、全部撤销/冲正事件以及成熟 GIS 空间推理。不能把当前值伪装成任意过去时点的状态。

观测与证据：
  观测、预测/模型断言、来源材料及评估状态分开；原件保留哈希与引用，证据撤回影响相关发布。
  哈希证明字节完整性，不证明材料真实性。已有基础冲突检查和人工评估记录，但没有通用来源可信度排序、自动真值评分或全面不确定性校准。
  原始文件和数据库之间尚无生产级分布式事务、资产生命周期管理与成熟孤儿文件清理机制。

约束与推理：
  已有 JSON 契约、外键及唯一性、数量和单位规则、事务幂等、租户权限、断言评估、物料影响查询和结构化推理资料包。
  尚未实现通用 OWL/SHACL 推理器、农业因果模型、任意规则执行、生产决策优化和自动设备控制。EvidenceBundle 为外部推理层提供有边界的数据，并不等于已经实现自动可靠决策。

七、农业产品溯源与二维码

内部可从批次查看上游物料、下游产出、事件和证据；消费者接口只返回审核后的公开字段和当前状态。EvidenceBundle 用于受控推理资料，TraceabilityBundle 用于业务溯源，公开 DTO 再从发布内容中按白名单生成。

二维码编码的是公开查询地址。随机公开码、二维码、哈希和一条已登记路径均不等于产品防伪、政府认证、GS1 认证或食品质量保证。项目没有获得或自动生成合法 GS1 编号，也没有完成 EPCIS 标准交换互操作认证。

默认二维码地址指向本机回环地址；手机上的 127.0.0.1 是手机自身，不能用它访问电脑。真实消费者扫码需要经过正式部署的可达 HTTPS 地址，并配置 AGRI_PUBLIC_BASE_URL、允许域名和生产鉴权边界。仅修改二维码前缀不会完成服务器发布。

发布后若新采纳的信息与公开声明出现同范围冲突，原发布会失效并记录审计；增量 outbox 的 review_assertion 事件包含 invalidated_publications，消费方必须处理此类失效提示。公开查询也再次核对当前冲突，不会因历史快照已生成而继续展示有效结论。

撤回证据和召回产品是两种不同动作。原件失效不会删除真实物料历史；消费者当前状态必须重新判断，不能用历史发布快照绕过已经发生的撤回或召回。

八、备份与恢复

SQLite 数据库在线备份使用 sqlite3.Connection.backup()，不是直接复制正在运行的 agri.db 文件。请在 implementation 目录执行：

  C:\ProgramData\anaconda3\python.exe ops/backup_sqlite.py backup --source data/agri.db --name agri-manual.db

验证备份：
  C:\ProgramData\anaconda3\python.exe ops/backup_sqlite.py verify --file data/backups/agri-manual.db

恢复到新的隔离文件：
  C:\ProgramData\anaconda3\python.exe ops/backup_sqlite.py restore --backup data/backups/agri-manual.db --name agri-restored.db

所有备份和恢复输出限定在 data/backups。工具拒绝覆盖现有目标文件，也不会直接替换活动数据库。恢复验证通过后，仍需停止应用、按受控切换步骤选择恢复库并检查业务状态；该工具不自动完成生产切换。

已验证活动 WAL 源库的一致性备份、未提交行排除、恢复后的数据库完整性、外键完整性和精确 Decimal 值。证据见 runtime/sqlite-backup-check.json。这不是 PostgreSQL 备份恢复或生产 RPO/RTO 验收。

特别注意：ops/backup_sqlite.py 只备份数据库。完整系统恢复还必须独立受控备份：
  - data/assets 中的原始图片、文档、视频等原件，并保存内容哈希清单；
  - contracts、领域包定义、映射、迁移脚本和与数据相匹配的应用版本；
  - 必需的运行配置及生产密钥，通过独立密钥管理和受控恢复渠道处理；
  - 发布配置、实际部署说明和恢复时所需的其他外部依赖。

数据库、原件和契约版本必须能一致对应。只有一个数据库备份文件，不能宣称已经完成全系统恢复。切勿将密钥和公开交付包混合分发。

九、PostgreSQL 与现有平台集成

migrations/001_core.sql 和 agri/db.py 提供 PostgreSQL 路径；requirements-postgresql.txt 声明所需驱动。ops/portable_pg.py 与 ops/POSTGRESQL_SETUP.txt 提供工作区独立开发实例的操作入口。

当前没有取得可运行的 PostgreSQL 服务，psycopg 安装和官方便携发行下载受环境网络权限限制。尚未执行真实 PostgreSQL SELECT version()、迁移、事务、并发、隔离或恢复验证。SQLite 的通过结果不能替代这些验收。

PostgreSQL 测试只应使用明确的专用测试 DSN，通过 TEST_DATABASE_URL 提供；测试会使用随机隔离 schema。不要把生产数据库连接串交给测试入口。

与真实梁子湖平台集成前，还需确认实际部署版本和 schema、主键映射、对象授权、生产事件与库存权威来源、事务 outbox 适配、幂等补偿、外部文件访问、质量审核与召回流程。当前没有生产投递 worker、完整 webhook 重试/死信、消费者回执运营或真实监管接口联调记录。

十、验证范围与交付状态

本轮已执行真实持久化 SQLite 业务测试、HTTP 边界测试、接入与文件安全测试、多维网络测试、公开投影与召回失效测试，以及在线备份恢复检查。最新测试结果与待办以本轮最终验收日志、IMPLEMENTATION_STATUS.json 和 database-gate.json 为准，本说明不固定写入易过期的测试总数。

浏览器验证使用独立浏览器环境，请求通过无端口的桥接进入真实 Flask 测试客户端和隔离 SQLite 数据库，没有用虚构 API 响应替代业务后端。已覆盖对象新增、主要工作视图、多维图、公开 DTO 与二维码、移动端布局，以及从界面撤回证据/召回后公开状态失效。

这类验证覆盖真实前后端业务交互，尚不覆盖 TCP 端口监听、网络代理、TLS、公网发布、真实扫码网络可达性、生产数据库和现场设备。浏览器测试使用隔离数据，不应修改默认演示库或真实生产系统。

在 implementation 目录可重新运行：
  C:\ProgramData\anaconda3\python.exe -m pytest tests -q

未设置专用 PostgreSQL 测试 DSN 时，对应测试会明确跳过。必须分别查看通过、失败和跳过项目，不能把跳过项目计算为已验收。

  4. 联调现有平台、实际采集设备和外部溯源消费方。
